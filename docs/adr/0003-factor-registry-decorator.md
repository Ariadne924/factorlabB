# 因子注册机制：装饰器 vs 手动注册

**上下文**：因子需要被评估框架和可视化模块统一发现。两种方案：(A) 装饰器自动注册 (B) 手动往字典里塞。

**决策**：两者都要——字典是存储，装饰器是入口。`FACTOR_REGISTRY: dict` 是单点真相，`@register_factor` 装饰器是唯一写入路径。

**理由**：
- 装饰器让因子定义和注册在同一位置，新人看一个文件就理解全貌
- 字典作为数据结构让查询（`get_factor_metadata`/`list_factors`）变成 O(1) 操作
- 禁止手动写入 FACTOR_REGISTRY 防止"注册了但装饰器没调"或反之的不一致

**废弃的方案**：纯手动注册——因子散落在四个子目录，手写字典容易漏、容易冲突。
