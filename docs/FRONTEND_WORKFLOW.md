# 前端研究工作流

当前 Streamlit 前端采用任务导向导航，不再要求用户先理解所有研究模块。默认路径为：

```text
开始使用 → 数据中心 → 策略研究 → 稳健性验证 → 结果比较
```

因子检验和机器学习仍然保留，但属于研究工具，不再阻塞用户先使用正式 registry 构建策略。

因子检验统一使用一个侧边栏入口，页内分为“单资产因子”“截面因子”和
“跨资产 / 跨频率”三个标签。三类结果仍按各自口径计算，只合并浏览入口，避免用户在多个
功能相近的页面之间来回寻找。

策略相关功能也统一使用“策略研究”入口，页内分为“单币种择时”“多币种选币”和
“结果比较”。三个模式共享导航和数据状态，但仍分别使用原来的时序与截面回测逻辑。

## 首页状态

首页根据本地 `data_catalog.json`、数据健康报告和当前 Streamlit 会话结果动态计算四个阶段：

1. 准备数据；
2. 选择候选因子（可后置）；
3. 构建策略；
4. 验证与比较。

状态口径：

- `blocked`：前置数据或回测结果不存在；
- `attention`：已有部分能力可用，但数据范围或缺口尚未收口；
- `ready`：前置条件满足，可以开始；
- `completed`：对应流程产物已经生成。

`completed` 只描述工作流，不代表完成六个月锁定 OOS，也不代表策略或因子已经验证有效。

## 数据任务队列

数据中心把健康检查结果转换成按优先级排序的行动项：

- P0：缺少核心币种/频率，或存在内部 K 线缺口；
- P1：历史可研究但近端行情陈旧，或 Funding/OI/Basis 尚未落盘；
- 已完成：核心覆盖、内部缺口和衍生品文件均满足当前基础要求。

行情刷新、目录扫描和范围参数收进高级操作区，避免用户进入页面后先面对大量输入控件。
覆盖表支持按币种、频率和状态筛选。

## 策略操作路径

策略研究中的“单币种择时”按照以下顺序组织：

1. 选择达到研究门槛的数据口径；
2. 查看历史天数和覆盖率；
3. 选择因子；
4. 在折叠区配置方向和权重；
5. 选择回测区间；
6. 按需展开高级执行参数；
7. 运行回测并查看实时任务状态；
8. 继续完成成本、市场状态和 Walk-Forward 诊断。

机器学习与策略回测等耗时操作使用可见的阶段反馈。数据健康扫描采用 30 秒缓存，并在目录重建后
主动失效，避免页面每次交互都重复读取全部本地状态。
